# POS System Changes — 2026-07-29

## Overview
This document captures all changes made to the pharmacy POS system on **2026-07-29**. The work focused on three areas:
1. Simplifying the customer credit / checkout payment flow
2. Removing the credit limit feature
3. Fixing runtime issues (blank screen + McKesson auto-import SQLite parameter limit)
4. Restoring the full checkout UI with product search, selectable items, and responsive layout

---

## 1. Credit System Simplification

### Problem
The original checkout "Tender" section was overcomplicated:
- It exposed a separate "Pharmacy Credit tender" input that confused cashiers
- It had a dedicated `TAB` tender type alongside `CASH`, `CARD`, and `SPLIT`
- Overpayment handling was buried in JSX rather than presented as clear options
- Underpayment had no clear path unless the cashier manually entered a tab amount

### Solution
Redesigned the payment UI and data model to be cashier-friendly:

#### a) Removed `TAB` as a separate tender type
**File:** `src/shared/types.ts`
- `CreateTransactionPayload.tenderType` changed from `'CASH' | 'CARD' | 'SPLIT' | 'TAB'` to `'CASH' | 'CARD' | 'SPLIT'`
- `tabAmountCents` remains on the payload, but is now just an amount field rather than a tender mode
- `cashOverageToCreditCents` remains for depositing cash overpayment to customer credit

#### b) Simplified CheckoutScreen payment section
**File:** `src/renderer/src/screens/CheckoutScreen.tsx`

**Before:**
- "Tender" card with:
  - "Cash tendered" input
  - Separate "Pharmacy Credit tender" input (showed current balance, allowed manual entry)
  - "Complete Cash Sale" and "Charge Card" buttons
  - Hidden logic for `tabDollars` state

**After:**
- "Payment" card with:
  - Single "Cash received" input
  - **Overpaid path:** Shows "Give change ($X)" and "Deposit $X to credit" buttons
    - Deposit option requires a customer to be attached; otherwise shows disabled state with tooltip
  - **Underpaid path:** If customer attached, shows "Put $X on [Customer]'s tab" button
    - If no customer attached, shows warning: "Not enough cash. Attach a customer to put the remaining $X on their tab."
  - Bottom action buttons: "Pay Cash" and "Pay Card"

**Behavior changes:**
- Removed `tabDollars` state entirely; tab amount is derived from `shortCents` automatically
- `completeSale()` signature changed from `(tenderType: string, _customerId?, depositCents?)` to `(tenderType: 'CASH' | 'CARD' | 'SPLIT', tabAmountCents?, cashOverageToCreditCents?)`
- Customer attachment card now shows live credit balance (`Credit: $X` or `Owes: $X`)

#### c) Updated tests
**File:** `src/__tests__/customerCreditQueries.test.ts`
- Removed `creditLimitCents` parameter from test helper
- Removed test: "blocks a charge that breaches the credit limit"
- Changed `tenderType: 'TAB'` to `tenderType: 'SPLIT'` in remaining tests to match new type

## 3. Blank Screen Fix — Restored Missing `customer` API

### Problem
The Electron app was showing a blank screen on startup. TypeScript errors in the console showed that `window.api.customer` was undefined in `CheckoutScreen`, `CustomersScreen`, and `SettingsScreen`.

### Root Cause
The `customer` API object was accidentally removed from `src/preload/index.ts` in a prior commit. The main process still had the IPC handlers registered (`src/main/ipc/customerHandlers.ts`), but the renderer could not call them because the preload bridge no longer exposed `window.api.customer`.

### Solution
**File:** `src/preload/index.ts`

1. Added `Customer` to the type imports from `../shared/types`
2. Added the full `customer` object to the `api` constant, restoring these methods:
   - `search(query)`
   - `get(id)`
   - `create(input)`
   - `update(id, input)`
   - `findDuplicatePhone(phone, excludeId?)`
   - `addFunds(customerId, amountCents, note?)`
   - `adjustCredit(customerId, amountCents, note, managerGranted)`
   - `adjustPoints(customerId, points, note, managerGranted)`
   - `getCreditSettings()`
   - `saveCreditSettings(input)`

**Note:** The input types for `create` and `update` were intentionally left without `creditLimitCents` to match the current schema.

## 4. McKesson Auto-Import SQLite Parameter Limit Fix

### Problem
When running `catalog:autoImport` with a large WEBCAT file, the import crashed with:
```
Query parameter limit exceeded error: Parameter limits for this database provider
require this query to be split into multiple queries, but the negation filters
used prevent the query from being split.
```

### Root Cause
In `autoImportCatalog()` at line 805 of `src/main/catalog/importService.ts`, the code was querying for "new" products using:
```ts
db.product.findMany({
  where: {
    origin: 'CATALOG',
    lastSeenBatchId: batch.id,
    sourceItemNumber: { notIn: [...previousItemNumbers] }
  }
})
```
When `previousItemNumbers` contained 65,000+ item numbers from the previous catalogue, SQLite's parameter limit (~999) was exceeded because each `notIn` value becomes a bound parameter.

### Solution
**File:** `src/main/catalog/importService.ts`

Changed the "new items" detection from a database-side `notIn` filter to an in-memory filter:

1. Query all products for the current batch without the `notIn` clause:
```ts
const batchProducts = await db.product.findMany({
  where: {
    origin: 'CATALOG',
    lastSeenBatchId: batch.id
  },
  select: { ... },
  orderBy: { name: 'asc' }
})
```

2. Filter in JavaScript using a `Set`:
```ts
const newProducts = batchProducts.filter(
  (p) => p.sourceItemNumber != null && !previousItemNumbers.has(p.sourceItemNumber)
)
```

This avoids the SQLite parameter limit entirely because the large set membership test happens in memory, not in the SQL query.

## 5. Checkout UI Restoration

### Problem
The checkout screen had been simplified too aggressively in a prior change, removing:
- The product search bar
- The selectable product grid
- The responsive two-column layout

This made it impossible for cashiers to browse and add products without a barcode scanner.

### Solution
**File:** `src/renderer/src/screens/CheckoutScreen.tsx`

Restored the full checkout layout while keeping the simplified payment logic:

#### Layout
- **Top:** Scan feedback banner + customer attachment bar (with live credit balance)
- **Left column (7/12):** Product search input + scrollable 2-column product grid
  - Each product card shows name, SKU, cost, and price
  - Clicking a product adds it to cart
- **Right column (5/12):** 
  - Cart card with line items, quantity controls, subtotal/tax/total
  - Payment card with simplified cash/card flow

#### Features restored
- Product search by SKU, name, or barcode
- Clickable product grid with visual cards
- Responsive 12-column grid that fits the screen
- Cart with quantity +/- buttons
- Barcode scanner integration with pause refs for search/tender inputs
- Customer search with dropdown results
- Quick-add customer form (from original UI)

#### Kept from simplified version
- Overpaid: "Give change" vs "Deposit to credit" buttons
- Underpaid: "Put $X on customer's tab" button
- No separate `TAB` tender type
- No credit limit enforcement
